# AGENTS.md

## 适用范围

本文件适用于 `plus-ui-ts/` 前端工程。根目录 `AGENTS.md` 仍然有效；若本文件与根目录规则冲突，以更具体的前端规则优先。

## 前端技术基线

- Vue 3
- TypeScript
- Vite 6
- Element Plus
- 前端端口：`9999`
- API 代理：`/dev-api` -> `http://localhost:9888`

## 目录与边界

1. 页面、路由、API、类型、组件放置规则优先沿用现有项目结构。
2. 新增页面必须确认菜单入口、路由路径、权限标识、页面标题和返回路径。
3. 新增 API 调用应放入对应业务 API 文件，并补充 TypeScript 类型。
4. 公共组件只在出现真实复用需求时抽取，不为单个页面提前抽象。
5. 不得引入与现有 UI 框架冲突的新组件库。
6. 修改共享组件、全局状态、路由守卫、请求封装前，必须确认影响范围。

## 前端规格要求

每项展示与输入必须明确：

1. 控件形态。
2. 数据来源。
3. 展示转换。
4. 默认值。
5. 约束规则。
6. 权限与状态控制。
7. 点击、跳转、筛选承接方式。
8. 提交后结果和异常反馈。

列表必须明确是表格、树、卡片或其他形态。

## UI 与交互规则

1. 优先使用 Element Plus 现有组件和项目已有封装。
2. 表格必须确认列、筛选项、排序、分页、批量操作、行操作和空状态。
3. 表单必须确认必填、格式校验、默认值、禁用态、提交态和错误反馈。
4. 弹窗必须确认打开来源、标题、确认动作、取消动作、关闭后是否刷新。
5. 按钮必须确认权限、加载态、防重复提交和异常提示。
6. 字典、状态、枚举展示优先复用项目已有转换方式。
7. 不得用大段说明文字替代清晰控件和状态设计。

## API 与类型

1. 请求路径、参数结构和响应结构必须与后端接口保持一致。
2. 新增或修改接口时，同步更新 API 方法、请求类型、响应类型和页面使用处。
3. 不得在页面中散落硬编码 URL；统一放入对应业务 API 文件。
4. 不得用 `any` 掩盖已知接口结构；确实未知时必须说明原因。
5. 删除或改名字段前，必须确认所有页面引用和后端兼容性。

## 权限、路由与状态

1. 涉及权限按钮、菜单权限或数据范围时，必须与后端权限点对齐。
2. 新增路由必须确认是否缓存、是否隐藏、是否需要面包屑、是否携带参数。
3. 从其他页面跳转携带筛选条件时，必须说明承接字段、默认行为和重置行为。
4. 列表筛选条件应能正确传递到后端，并支持重置。
5. 提交、删除、导入、导出等操作必须处理成功提示、失败提示、加载态和刷新逻辑。

## 前端验证命令

默认在 `plus-ui-ts/` 目录执行；若当前位于仓库根目录，先进入 `plus-ui-ts/`。

常规检查：

```bash
npm run lint:eslint
npm run build:prod
```

本地启动：

```bash
npm run dev
```

依赖缺失或锁文件变化时才运行：

```bash
npm install
```

## 交付要求

前端变更交付时说明：

1. 涉及页面、路由、API、组件和权限点。
2. 是否影响共享组件、全局状态、路由守卫或请求封装。
3. 已运行的 lint/build 命令。
4. 关键页面和关键交互的烟测结果。
5. 未验证项、原因和残余风险。
6. 回滚方式。
