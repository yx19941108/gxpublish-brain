# R6.19_WP6-G1-BPM执行基线

## 1. 目的与替代边界

- 本文是当前 `WP6-G1` BPM 线的最新执行基线。
- 本文只收口本轮已经拍板的 BPM 相关口径，不重开 `R7`，不启动前端开发包。
- 后续若与以下文档出现冲突，以本文为准：
  - `doc/manuscript_review/R6.18_WP6-G1-M1执行侧续工提示词.md`
  - `doc/manuscript_review/R6.17_WP6-G1主控审批结论.md`
  - `doc/manuscript_review/R5.7_第6-7轮执行基线.md`
  - `doc/manuscript_review/R5.5_冻结契约包.md`
- 本文不推翻业务闭环，只修正“BPM 办理页如何承载”的执行口径。

## 2. 当前轮次目标

- 当前轮次目标仍是：闭环后端 `manuscript_review` 的 BPM/runtime 主线。
- 当前轮次不做：
  - `plus-ui-ts/**` 前端实现
  - `Brain/brain-modules/brain-workflow/**` 通用 Java 改造
  - shared 输出形态扩容
  - `R7` 讨论或前端交互实现包
- 代码落点可以延续现有仓库路径，但旧有失败逻辑不得复用，不得把旧失败实现当基线续写。

## 3. BPM 页面口径

### 3.1 统一结论

- `manuscript_review` 仍然遵守“详情页点去审批后进入办理页”的业务闭环。
- 但这里的“复用现有 BPM 办理页”不再解释为“复用现成旧业务页面”。
- 统一改写为：
  - 复用现有 BPM 跳转机制
  - 复用现有 workflow 任务办理接口
  - 复用现有通用审批模态框与流程进度组件
  - 新建 `manuscript_review` 专属审批页作为办理页承载

### 3.2 `formPath` 口径

- `formPath` 由后端定义。
- 当前 BPM 基线默认写死为：
  - `/manuscript/review/approval`
- 不再使用以下页面作为 BPM 办理页：
  - `/manuscript/review/form`
  - `/manuscript/review/detail`

### 3.3 页面职责边界

- 详情页：
  - 负责查看稿件
  - 负责显示“去审批”入口
  - 不直接完成审批
- 审批页：
  - 是独立页面
  - 只承载审批态只读展示
  - 只允许：
    - 点击“审批”打开通用审批模态框
    - 点击“流程进度”打开通用流程进度组件
  - 不允许：
    - 修改主单
    - 启停附件
    - 启停外链
    - 视频批注增删改停
    - 任何“修改保存”类动作

## 4. 后端执行口径

### 4.1 保持不变

- `processType -> flowCode`
  - `AUDIT -> manuscript_review_audit_flow`
  - `PROOFREAD -> manuscript_review_proofread_flow`
- workflow `businessId` 直接复用主表 `reviewId`
- `brain-manuscript-review` 仍只作为代码落点，不作为反推冻结契约的依据

### 4.2 本轮允许推进的事

- manuscript 侧接通真实 workflow 发起、再次提交、撤销
- manuscript 侧新增 `ProcessEvent / ProcessTaskEvent` 最小监听与回写
- manuscript runtime 资产可以先行定义：
  - `runtime_<flowCode>_v01.json`
  - 分层 SQL seed / rollback
- 这些资产里的 `formPath` 必须与本文保持一致

### 4.3 本轮不允许推进的事

- 以前端实现是否已存在为借口，继续沿用旧 `form.vue` 或旧 `detail.vue` 作为 BPM 办理页
- 因前端未开工而回退到“先猜一个旧页凑合”
- 修改 shared detail VO 去承载新的审批页面设计
- 修改 workflow 通用 Java 代码去兜底前端未开工问题

## 5. runtime 资产口径

- 当前两条流程定义仍分开保留：
  - `manuscript_review_audit_flow`
  - `manuscript_review_proofread_flow`
- 如果本轮继续保留或新增 runtime JSON / SQL：
  - `flowCode` 仍按上面两条
  - `formPath` 必须改为 `/manuscript/review/approval`
- 在前端未开工的前提下，允许后端先定义该 `formPath` 作为正式基线，后续前端按该路径补页面。

## 6. 验证目标不变

- 本轮后端验证目标仍以 `R6.18` 为准，至少覆盖：
  - `FR-05` 撤销闭环
  - `FR-06` 三级驳回终止闭环
  - `FR-07 / FR-08 / PM-06 / NE-06` 的后端/BPM 侧真实约束
- 其中“去审批”的真值口径更新为：
  - `permissionMatrix + formPath + taskId`
  - 但 `formPath` 的页面承载改为 manuscript 专属审批页，而非旧 `form/detail`

## 7. 后续提示词使用规则

- 后续执行提示词或 handoff，如涉及 `manuscript_review` BPM 页面口径，必须先读本文。
