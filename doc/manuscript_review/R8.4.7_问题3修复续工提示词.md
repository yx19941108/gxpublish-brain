# R8.4.7_问题3修复续工提示词

## 1. 使用时机

本文件用于新会话直接承接 `gxpublish-brain / manuscript_review / 问题 3 修复`。

本文件不是新的方案讨论文档，不重新比较“历史参与人兜底”与“发起/待办/已办”两条路线，而是把问题 3 的最新冻结口径与执行要求压缩落盘。

## 2. 执行入口

下一轮开场先读以下文件，不得跳过：

1. `doc/manuscript_review/R8.2_问题池统一修复方案.md`
2. `doc/manuscript_review/R8.3_问题池分轮修复执行基线.md`
3. `doc/manuscript_review/R8.2.5_问题池统一回归测试用例.md`
4. `doc/manuscript_review/R8.4.6_问题3台账口径冻结.md`
5. 本文件 `doc/manuscript_review/R8.4.7_问题3修复续工提示词.md`

裁决规则：

1. 问题 3 的业务口径以 `R8.4.6` 为准
2. 若 `R8.2 / R8.3 / R8.2.5` 与 `R8.4.6` 冲突，以 `R8.4.6` 为准
3. 本轮只处理问题 3，不顺手扩到其他问题

## 3. 本轮硬边界

本轮只修问题 3，范围锁死为：

1. 修正台账可见性口径
2. 修正台账行级操作权限口径
3. 修正台账页“新增”按钮显隐
4. 不进入问题 1 / 4 / 5 / 6 / 7 / 8 / 9
5. 不再使用“历史参与人兜底可见”口径

## 4. 已冻结口径

### 4.1 发起人

1. 菜单：`台账`、`我发起的`
2. 台账可创建
3. 台账只看 `我发起的`
4. 台账不具备审批操作

### 4.2 审批人

1. 菜单：`台账`、`我的待办`、`我的已办`
2. 台账不可创建
3. 台账看 `我的待办 ∪ 我的已办`
4. 仅 `我的待办` 可 `去审批 / 修改`
5. `我的已办` 仅查看

### 4.3 发起人混合审批人

1. 菜单：`台账`、`我发起的`、`我的待办`、`我的已办`
2. 台账可创建
3. 台账看 `我发起的 ∪ 我的待办 ∪ 我的已办`
4. 仅 `我的待办` 可 `去审批 / 修改`

## 5. 本轮固定结论

1. 问题 3 不再采用“发起人来源 ∪ 审批人来源 ∪ 历史参与人来源”
2. `history.actor_user_id` 不再是问题 3 的默认兜底可见来源
3. “可见”不等于“可操作”
4. 不能只改 `listLedger`

## 6. 实现要求

至少要同步处理三处：

1. 台账列表查询
2. 台账行级操作权限判定
3. 台账页“新增”按钮显隐

推荐实现方向：

1. 后端基于三类权威来源先求可见 `businessId/reviewId`
   - 我发起的
   - 我的待办
   - 我的已办
2. 再回主表做数据库级筛选、排序、分页
3. 行级 `canApprove / canEdit` 单独计算，仅对“我的待办”开放审批型动作

## 7. 本轮先输出

1. 已确认
2. 风险
3. 待确认
4. 推进方案

然后给出本轮代码变更计划。每一步必须包含：

1. Goal
2. Affected Files
3. Risk
4. Verification
5. Rollback

## 8. 本轮回归要求

至少覆盖：

1. 发起人台账只看到 `我发起的`
2. 审批人台账看到 `我的待办 ∪ 我的已办`
3. 混合角色台账看到三者并集
4. 发起人可创建，审批人不可创建，混合角色可创建
5. 仅“我的待办”记录展示 `去审批 / 修改`
6. `我的已办` 与 `我发起的` 记录不展示审批型操作
7. 新建用户不因历史参与记录看到旧流程数据

## 9. 禁止事项

1. 不得再把 `history.actor_user_id` 当台账兜底可见来源
2. 不得只改列表 SQL，不改行级操作权限
3. 不得把“新增按钮显隐”留给后续再补
4. 不得顺手扩到其他问题
