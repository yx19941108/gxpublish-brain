### 5.6 游工意见：方案不通过。使用下面的方案第一轮修复。
你的这个方式是从待办已办发起列表先查询出businessId，然后再分页到数据库主表查，这是不对的。假设后续还上了其他流程的功能（非三审三校），那么数据是不一致的，没有任何扩展性。我的修复方案大致是：
1. 通过roleKey查询出三审三校相关的角色（roleKey由系统枚举写死）；
2. 查询当前用户拥有的三审三校角色，每个角色都有对应的brian_manuscript_review的current_node_status，例如：一级审批人对应LEVEL_1，二级审批人对应LEVEL_2，三级对应LEVEL_3；然后如果用户有多个审批人角色把对应的状态加入查询状态集合，例如：用户同时是一二级审批人，则查询状态集合未["LEVEL_1", "LEVEL_2"]。
3. mapper.xml写SQL条件片段：
```java
where 其他查询条件 and (<trim xxxx> #用于正确拼接and/or这些关键字
   <if test hasInitial>
      or brain_manuscript_review.create_by = #{userId}
   </if>
   <if test isAuditor>
      or (brain_manuscript_review.current_node_status in (foreach{查询状态集合}))
   </if>
   or exsits (select 1 form brain_manuscript_review_history where brain_manuscript_review = brain_manuscript_review_history.review_id and actor_user_id = #{userId}))
<trim>)
```
需要注意，当前我发现brain_manuscript_review_history中actor_user_id很多时候是空的，使用这种方式，记得写入要正确带入actor_user_id，按理说任何时候这个字段都不为空。

## 10. 问题 8：资源预览链路错误依赖 OSS 直链 / `127.0.0.1`

### 10.1 问题描述

当前资源预览链路依赖：

1. OSS 预签名 URL
2. 或原始 `fileUrl`

而当前 OSS 服务 `9000` 端口本身不对外暴露，所以即使改 `sys_oss_config`，也不能把“预览主能力”继续建立在 OSS 直链上。

### 10.2 是否确认

1. 已确认。

补充结论：

1. 通过修改 `sys_oss_config` 可以缓解一部分地址问题。
2. 但根本问题不是配置字符串，而是“预览方案选错了”。
3. 主预览方案应改为：
   - 后端同域中转
   - 浏览器原生预览
   - 不再依赖 OSS 对外暴露预览地址

### 10.3 修复方案

#### 后端方案

新增 manuscript-review 模块内资源预览接口，后端读取 OSS 内容后，以同域 HTTP 响应流形式返回给浏览器。

目标：

1. PDF 走浏览器新标签页原生预览
2. 视频走 `<video>` 原生播放
3. 对视频支持 `Range` / `206 Partial Content`
4. 下载仍保留单独 download 接口

后端伪代码：

```java
@GetMapping("/resource/preview/{resourceId}")
@SaCheckPermission("manuscript:review:detail")
public void previewResource(@PathVariable Long resourceId,
                            HttpServletRequest request,
                            HttpServletResponse response) {
    PreviewResource resource = manuscriptReviewPreviewService.requirePreviewable(resourceId, currentUserId());
    InputStream in = ossGateway.open(resource.getOssId());
    String mime = resolveMime(resource);

    response.setContentType(mime);
    response.setHeader("Content-Disposition", "inline; filename*=UTF-8''" + urlEncode(resource.getFileName()));

    if (resource.isVideo() && request.getHeader("Range") != null) {
        streamPartialContent(in, request, response, resource.getContentLength(), mime);
        return;
    }

    streamFullContent(in, response);
}
```

关键点：

1. 不返回 OSS 预签名 URL 给前端
2. 浏览器看到的是本系统同域接口地址
3. PDF / 图片等可被浏览器直接 inline 预览
4. 视频必须补 `Range` 支持，否则进度条问题仍可能出现

#### 前端方案

1. `plus-ui-ts/src/views/manuscript-review/detail-page-shell.vue`
   - 位置 A：视频播放器 `:src="activeVideo.resourceUrl"`
   - 修改：`activeVideo.resourceUrl` 不再是 OSS URL，而是模块内 preview URL
   - 位置 B：资源操作区 `preview`
   - 当前：`openExternalTarget(item.resourceUrl)`
   - 修改：继续 `window.open(...)`，但打开的是同域 preview URL
2. `detail.contract.ts`
   - 明确 `resourceUrl` 语义从“OSS 可读地址”收敛成“模块预览地址”
3. 对无法原生预览的 MIME：
   - 前端只保留下载，不展示预览

### 10.4 覆盖文件

后端：

1. `Brain/.../ManuscriptReviewReadableService.java`
2. 新增 preview controller / service / gateway
3. 可能联动 `Brain/.../SysOssController.java` 或新增 manuscript-review 专属 preview 流实现
