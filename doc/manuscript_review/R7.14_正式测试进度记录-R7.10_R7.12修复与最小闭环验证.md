# R7.14_正式测试进度记录-R7.10_R7.12修复与最小闭环验证

## 1. 本轮目标

本轮不继续全量正式测试，只完成两件事：

1. 修复 `R7.10`：审批/退回动作成功后，不再错误回跳到当前账号已无权读取的 detail 页。
2. 修复 `R7.12`：退回后发起人进入 edit 页时，既有 detail data 能被正确承接，且保存不推 BPM、再次提交能回到 `待一级审批`。

## 2. 本轮代码落点

### 2.1 `R7.10` 前端承接修复

本轮把承接规则从 `.vue` 内联跳转改成可测试的纯函数层：

- 新增：`plus-ui-ts/src/views/manuscript-review/detail-navigation.ts`
- 接入：
  - `plus-ui-ts/src/views/manuscript-review/detail-page-shell.vue`
  - `plus-ui-ts/src/views/manuscript-review/form.vue`

落地口径：

1. edit 页从 detail 进入时，`returnTo` 固定带上当前 detail 路由。
2. approval 页从 detail 进入时，`returnTo` 固定带上当前 detail 路由。
3. approval 页点击 `返回`：
   - 若来自 detail：回 detail
   - 若来自 workflow 待办入口：回 `workflow/task/taskWaiting`
4. detail 页点击 `返回`：
   - 若来自 workflow 待办入口（`type=view + taskId`）：回 `workflow/task/taskWaiting`
   - 否则回 `manuscript-review` 台账列表
5. approval 动作成功后统一回 `manuscript-review` 台账列表，不再二次读取无权 detail。

### 2.2 `R7.12` edit 回填修复

本轮确认 root cause 不在接口无数据，而在 edit 页直接吃原始 detail payload，未走 detail 页同一套规范化链。

修复方式：

- `plus-ui-ts/src/views/manuscript-review/components/formState.ts`
  - 新增 `createDraftStateFromPayload(payload)`
  - 内部复用 `normalizeDetailViewModel(payload).detail`
- `plus-ui-ts/src/views/manuscript-review/form.vue`
  - edit 加载改为使用 `createDraftStateFromPayload`
  - save/back 改为复用新的 `returnTo` 承接规则

结果：

1. 流程类型、标题、媒体栏目、作者、说明、正文进入 edit 表单。
2. 既有外链进入 `当前已入库资源` 区，不再出现“已入库资源区空白”。
3. save 后仍回 detail，且业务状态保持 `已退回 / 待发起人处理`。
4. resubmit 后回到 `审批中 / 待一级审批`。
