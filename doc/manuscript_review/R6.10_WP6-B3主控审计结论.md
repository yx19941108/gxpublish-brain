## 3. 当前剩余 blocker

### 3.1 核心问题

以下写动作目前仍未看到与 `update` 同级的 record-level 修改权守卫：

- `addResource`
- `disableResource`
- `addVideoMark`
- `disableVideoMark`

当前代码现状：

- `update` 已调用 `ensureCanModify(existing)`。
- 但上述 4 个动作仅做了对象存在性/格式/时长等校验，未在服务层统一校验“当前用户是否具备修改权”。

这与冻结材料冲突点如下：

- PRD 要求只有具备修改权的用户才可修改流程资料。
- PRD 要求详情页可直接新增/停用标注，但动作权限仍受“可审即可改 / 被退回发起人可改 / 其他人不可改”约束。
- 因此当前实现若仅依赖前端按钮矩阵而无后端守卫，不能判定为闭环可信。

### 3.2 为什么这会阻断 `WP6-G1`

- `WP6-G1` 是 gate，不是修复包。
- `R5.7` 对 `WP6-G1` 的定义是：
  - `Affected Files：无新增实现范围，只做 Gate 判断`
- 只要仍存在会影响 `NE-06 / PM-01 / PM-06` 口径的后端越权写风险，就不能按“第6轮 P0 必测集已稳定”放行。
