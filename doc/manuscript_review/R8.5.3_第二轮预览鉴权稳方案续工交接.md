## 3. 当前真正锁定的新根因

### 3.1 不是后端 preview 接口没通

后端接口实测已通：
1. 附件 preview：
   - `GET /workflow/manuscript-review/resource/preview/2038640763473829890`
   - 携带：
     - `Authorization: Bearer <token>`
     - `clientid: e5cd7e4891bf95d1d19206ce24a7b32e`
   - 返回：
     - `HTTP 200`
     - `Content-Type: application/pdf;charset=UTF-8`
     - `Content-Disposition: inline`
2. 视频 preview：
   - 同样携带 `Authorization + clientid`
   - 带 `Range: bytes=0-1023`
   - 返回：
     - `HTTP 206`
     - `Content-Range`
     - `Accept-Ranges: bytes`
     - `Content-Type: video/mp4;charset=UTF-8`

结论：
1. 后端模块内 preview 能力已经成立
2. PDF inline 与视频 Range/206 在接口层都成立

### 3.2 当前浏览器 red 的根因是“原生资源请求不带登录态”

当前浏览器运行态证据：
1. 详情页已能看到：
   - 退回态详情
   - 新增视频标注操作区
   - 新增后标注列表与时间线刷新成功
2. 但浏览器资源请求仍失败：
   - PDF 预览页仍是 404 / 空白
   - 视频：
     - `currentSrc = http://127.0.0.1:9999/dev-api/workflow/manuscript-review/resource/preview/...`
     - `readyState = 0`
     - `currentTime = 0`

关键结论：
1. 前端详情现在把资源地址从 `/workflow/...` 修正成了 `/dev-api/workflow/...`
2. 这说明“是否经过 Vite 代理”已不是唯一问题
3. 当前更深层问题是：
   - 浏览器原生的 `window.open(...)`
   - 浏览器原生的 `<video src="...">`
   不是 axios 请求
4. 它们不会自动携带：
   - `Authorization`
   - `clientid`
5. manuscript-review preview endpoint 目前仍依赖当前登录态鉴权
6. 所以：
   - 单测/API 手工带 header 时是绿的
   - 浏览器原生预览/播放时仍是红的

这就是本轮“代码级 green，但浏览器 gate 未通过”的真实原因。

## 4. 游工已明确选择的方向

游工已明确：
1. 不走“把 Bearer token 直接拼进 URL”的快方案
2. 走“稳方案”

当前对“稳方案”的定义固定为：
1. 不把长期登录 token 直接暴露到资源 URL
2. 仍然让浏览器原生 preview / video 能访问资源
3. 资源鉴权要与当前登录态绑定
4. 方案要能支撑：
   - PDF inline
   - 视频 `Range / 206`
   - 非 OSS 本机访问

## 5. 推荐的稳方案口径

推荐口径：
1. 新增 manuscript-review 专用短时效 preview token
2. 页面先用正常登录态向后端申请“资源级短期票据”
3. 浏览器真正打开/播放的地址改为：
   - `/dev-api/workflow/manuscript-review/resource/preview/{resourceId}?previewToken=...&clientid=...`
4. 后端 preview endpoint 增加：
   - 登录态直连校验
   - 或 previewToken 校验
5. previewToken 必须满足：
   - 绑定 `resourceId`
   - 绑定 `userId`
   - 绑定 `clientid`
   - 有较短过期时间
   - 仅允许 preview，不扩成通用登录 token

不建议的做法：
1. 不要把 Bearer token 直接塞进 URL
2. 不要回退到 OSS 直链 / 预签名 URL 作为主方案
3. 不要把问题 4 再拆成独立实现
4. 不要顺手进入问题 6
