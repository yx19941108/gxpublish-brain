# R9.0_问题池汇总与修复准备

## 1. 文档定位

本文用于汇总 `gxpublish-brain / manuscript_review` 当前已和游工对齐的优化项，作为 `R9` 阶段的执行入口。

本文只沉淀当前已经明确的问题、默认口径与后续修复边界，不在本文内展开代码实现。

## 2. 已冻结口径

1. 问题 5 中“操作人、操作时间”默认口径采用“该当前有效项的创建人/创建时间”。
2. 不采用“最近一次启用/停用它的人和时间”作为详情展示默认口径。
3. 启用/停用动作继续以时间线为准，不把资源区展示改造成历史态摘要区。
4. 附件、视频、外链、视频标注四个资源区需要固定高度，内容超出时走区块内滚动。
5. 视频标注时间展示口径统一为：
   - 有结束时间时展示“开始时间 - 结束时间”
   - 无结束时间时只展示开始时间
6. 登录后默认跳转口径拟统一到首页，避免把上一个用户的无权限页面带给下一个用户。

## 3. 审校模块问题池

### 3.1 表单与提交流程

1. 表单页“作者”字段前端没有必填标识，但后端实际强校验必填，前后口径不一致。
2. 多视频场景下，上方视频选择区切换后，下方“新增视频标注”区的“当前视频”下拉不会实时联动，容易误标到错误视频。
3. 审校流程创建完成后，修改页仍允许继续修改“流程类型”，而后端 `update(...)` 还会同步重写 `flowCode`，存在审校表与 BPM 流程编码不一致风险。
4. 上传大文件时没有进度反馈，也没有页面级阻断，用户容易误以为没上传成功而重复上传。

### 3.2 资源展示与交互

5. 详情页、审批页、修改页中的附件/视频展示不应直接暴露技术链接；外链可继续显示真实链接。
6. 附件、视频、外链、视频标注四类展示项都应补充“操作人、操作时间”；附件和视频还应补充“文件大小（MB）”。
7. 附件、视频、外链、视频标注四个区域的视觉高度应固定，内容超出时走区域内滚动，不能再被长文件名、长链接、长标注拉高整体布局。
8. 外链区域在只有 1 条外链时样式异常，按钮或条目会被拉大；多条时恢复正常。

### 3.3 视频标注专项

9. 视频标注被停用后，如果从历史里点击“启用”，原停用历史记录上的“启用”按钮应自动隐藏；当前实现不会隐藏。
10. 视频标注时间展示口径不统一。资源区有的地方只显示开始时间，有的地方显示开始时间到结束时间，需要统一。
11. 新增视频标注区域的校验提示现在出现在页面最上方，离操作区过远，容易让用户误以为按钮没反应；应改为在新增视频标注区域内就近提示。

## 4. 公共问题

1. 登录后跳转逻辑存在跨用户串页问题。退出登录时系统会把“退出前当前页”带到下次登录成功后继续跳转，导致 admin 从用户管理页退出后，普通审校用户登录会被带回无权限页面并 404。
2. 首页目前仍为默认 RuoYi 说明页，内容与视觉都未切换到“广西数智出版传媒有限公司 / 出版业务系统”的业务语义，需要先提供一版简单清晰的高保真设计稿，再决定是否实现。

## 5. 当前证据摘要

1. 前端 `form.vue` 中“作者”字段没有必填星号和规则，但后端 `ManuscriptReviewService#validateAuthorName(...)` 明确要求作者非空。
2. 前端 `detail-page-shell.vue` 中“新增视频标注”的 `pendingVideoMarkResourceId` 与上方 `activeVideoId` 并非实时联动。
3. 后端 `ManuscriptReviewService#update(...)` 会重新执行 `applyWriteFields(...)`，并执行 `entity.setFlowCode(resolveFlowCode(command.getProcessType()))`。
4. 前端上传区当前只有 `beforeUpload / onSuccess / onError`，缺少进度和阻断态。
5. 详情壳当前把附件/视频的 `resourceUrl` 作为资源说明展示，造成技术链接泄露。
6. 后端实体层已具备部分展示所需字段：
   - 附件/视频：`fileSize/createBy/createTime`
   - 外链：`createBy/createTime`
   - 视频标注：`createBy/createTime`
   - 历史：`actorUserId/actorName/createTime`
7. 登录串页根因在前端导航栏退出逻辑和登录成功后的 redirect 回跳逻辑，而非权限系统本身。

2. 首页问题在实现前应先完成高保真设计稿评审。
