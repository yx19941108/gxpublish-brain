### 3.2 仍失败但根因明确

#### 用例-41 发起人审批中撤销

真实浏览器 + 接口事实：

1. 发起人在 `我发起的` 对审批中样本执行撤销，确认框文案与按钮真实出现。
2. 撤销后详情状态真实变为：
   - `businessStatusLabel = 已取消`
   - `currentNodeLabel = 流程已取消`
3. 但时间线没有新增：
   - `eventCode = CANCEL`
4. 本轮样本时间线仍只有创建记录，没有撤销留痕。

根因：

1. 发起人列表页的撤销调用的是通用工作流接口：
   - `plus-ui-ts/src/views/workflow/task/myDocument.vue`
   - `cancelProcessApply` -> `/workflow/instance/cancelProcessApply`
2. 它没有走审校业务专用接口：
   - `/workflow/manuscript-review/cancelProcessApply`
3. 因此流程状态被工作流侧改掉了，但 `ManuscriptReviewService.cancelProcessApply(...)` 中的审校历史写入没有触发。

结论：

- `用例-41` 仍失败，但根因已明确。

#### 用例-48 退回或驳回目标节点只能选择申请人

真实接口事实：

1. 一级审批可退回节点为：
   - `applicant-node`
2. 二级审批可退回节点为：
   - `first-review-node`
   - `applicant-node`
3. 三级审批可退回节点为：
   - `second-review-node`
   - `first-review-node`
   - `applicant-node`

预期对比：

1. 各级都应只能选择：
   - `申请人`

根因：

1. 工作流服务 `FlwTaskServiceImpl.getBackTaskNode(...)` 在 `any_node_skip` 为空时，会退化为：
   - `previousNodeList(...)`
   - 再按历史节点回收全部前置审批节点
2. 当前稿件审校流程节点 `any_node_skip` 为空。
3. 虽然 `flow_skip` 已存在“退回到申请人”的显式 REJECT 跳转，但 `getBackTaskNode(...)` 并不按这些 REJECT 跳转收口目标集合。

结论：

- `用例-48` 仍失败，但根因已明确。

#### 用例-58 发起人待办列表中的查看、撤销、编辑按钮与跳转正确

真实浏览器事实：

1. 审批中样本行按钮为：
   - `查看`
   - `撤销`
2. 退回样本行按钮为：
   - `编辑`
   - `删除`
   - `查看`
3. 审批中样本 `查看` 真实跳到：
   - `/manuscript/review/detail?...`
4. 退回样本 `查看` 真实跳到：
   - `/manuscript/review/detail?...`
5. 退回样本 `编辑` 真实跳到：
   - `/manuscript/review/approval?id=...&type=update&taskId=...`
   - 而不是编辑页 `/manuscript/review/form?...`

预期对比：

1. 退回样本应仍可撤销。
2. 退回样本 `编辑` 应跳转到我们的编辑页。
3. 当前两点都不满足。

根因：

1. `myDocument.vue` 中撤销按钮只在：
   - `scope.row.flowStatus === 'waiting'`
   时显示，退回态未纳入。
2. `myDocument.vue` 的 `编辑` 仍走通用：
   - `workflowCommon.routerJump(...)`
3. 由于列表行 `formPath` 仍为：
   - `/manuscript/review/approval`
4. 所以退回态 `编辑` 被错误带到了审批承载页，而不是审校编辑页。

结论：

- `用例-58` 仍失败，但根因已明确。
