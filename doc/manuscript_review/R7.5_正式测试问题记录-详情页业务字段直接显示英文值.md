# R7.5_正式测试问题记录-详情页业务字段直接显示英文值

## 1. 这是什么问题

在正式浏览器测试里，`mr_initiator` 打开审校详情页后，页面把多项业务字段直接显示成英文值：

- 媒体栏目：`Xinhua/Headlines`
- 报送部门：`EditorialOffice`
- 作者：`qauser`

这和 `R7.4_正式测试方案-全需求覆盖.md` 里“页面展示遵守中文业务语义，不裸露英文枚举/技术值”的要求冲突。

## 2. 我是怎么复现出来的

1. 启动前端、后端、Redis。
2. 用浏览器访问 `http://127.0.0.1:9999/login?redirect=/index`。
3. 使用账号 `mr_initiator / 666666 / 1234` 登录。
4. 进入 `审校台账`。
5. 打开系统稿件号 `SH20260326003` 的详情页。
6. 观察“基本信息与状态摘要”区块。

## 3. 实际看到的结果

页面真实展示结果如下：

- 页面标题是“审校详情”，页面能正常打开。
- 但“媒体栏目 / 报送部门 / 作者”这几个字段直接显示英文内容。
- 这类内容对普通业务用户不友好，看上去像内部值、测试值或未转义的原始值。

## 4. 按当前正式测试方案，应该是什么结果

至少应该满足下面几点：

- 页面优先展示用户能直接看懂的中文业务内容。
- 不应该把英文枚举值、内部标识值、测试占位值直接裸露给业务用户。
- 如果当前数据源只有内部值，也应该在页面层做可读化处理，或者在样本层准备符合业务语义的数据。

## 5. 影响范围

这个问题会直接影响以下正式测试点：

- 页面职责与展示口径核对
- 详情页业务信息可读性
- 历史和页面整体是否符合真实用户使用习惯

如果不处理，这一轮正式测试里“页面展示遵守中文业务语义”相关用例应判失败。

## 7. 我对问题的判断

当前至少存在下面两种可能：

1. 页面没有把原始业务值转换成用户可读中文，导致内部值直接暴露。
2. 当前测试样本本身就不是按正式业务展示口径准备的，页面只是把不合格样本原样显示出来。

无论是哪一种，对正式测试来说都不能算通过。

## 8. 建议怎么处理

建议按下面顺序处理：

1. 先定口径：
   - 这些字段到底应该展示“中文业务名”，还是允许展示原始录入值。
2. 再分层修：
   - 如果要求中文展示，就在返回层或前端展示层做可读化处理。
   - 如果允许用户自由录入，那正式测试样本也必须换成真实业务口径的中文数据，不能继续用明显测试味道的英文占位值。
3. 修完后复测：
   - 同一条详情页重新检查“媒体栏目 / 报送部门 / 作者”三项展示。
   - 再抽查列表页、详情页、历史文案里是否还有同类英文直出。

这个问题已经在真实浏览器里复现，且有页面、接口、数据库三层证据支撑。
