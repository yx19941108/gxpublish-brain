## 3. 根因收敛

### 3.1 后端

`ManuscriptReviewReadableService.buildTimelineItems()` 原实现仅返回：

1. `eventTime`
2. `eventCode`
3. `eventText`
4. `operatorName`

未返回：

1. 资源类型
2. `ossId`
3. 资源 URL
4. 外链 URL

因此前端即便想做点击，也没有足够元数据。

### 3.2 前端

`detail-page-shell.vue` 时间线原实现只渲染：

1. `actionLabel`
2. `operatorName`
3. `remark`

未对历史中的资源名做结构化拆分，也没有绑定下载/跳转动作。

## 4. 本轮修复

### 4.1 后端

修改：

1. `Brain/brain-modules/brain-manuscript-review/src/main/java/com/gxpublish/brain/manuscript/review/controller/response/ManuscriptReviewDetailResponse.java`
2. `Brain/brain-modules/brain-manuscript-review/src/main/java/com/gxpublish/brain/manuscript/review/service/ManuscriptReviewReadableService.java`

修复内容：

1. `timelineItems` 新增返回字段：
   - `relatedResourceId`
   - `relatedResourceOssId`
   - `relatedResourceType`
   - `relatedResourceUrl`
   - `relatedExternalUrl`
2. 仅对 `RESOURCE_DISABLE` 历史做资源元数据回填，避免把其他历史动作误扩成链接语义
3. 对停用附件返回下载所需的 `ossId / resourceUrl`
4. 对停用外链返回跳转所需的 `externalUrl`

### 4.2 前端

修改：

1. `plus-ui-ts/src/api/manuscript-review/types.ts`
2. `plus-ui-ts/src/views/manuscript-review/detail.contract.ts`
3. `plus-ui-ts/src/views/manuscript-review/detail-page-shell.vue`

修复内容：

1. 前端时间线类型补齐后端新增元数据
2. 当历史项包含可点击资源元数据时，将文案拆成：
   - 前缀文本
   - 可点击资源名
   - 后缀文本
3. 附件历史名点击后走：
   - `proxy.$download.oss(ossId)`
4. 外链历史名点击后走：
   - `window.open(externalUrl, '_blank', 'noopener,noreferrer')`
5. 无元数据的历史项继续保持纯文本，不影响既有历史展示
