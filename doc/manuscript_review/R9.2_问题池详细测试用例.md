## 3. 前置数据要求

### 3.1 必备样本

执行前至少准备以下业务样本：

1. `样本 A：普通发起草稿`
   - 由 `mr_initiator` 创建
   - 有正文
   - 暂存 1 个附件
   - 暂存 1 个视频
   - 暂存 1 条外链
2. `样本 B：已提交并可修改样本`
   - 已进入流程
   - 当前允许“修改保存”或“再次提交”
3. `样本 C：多视频样本`
   - 至少 2 个有效视频
   - 每个视频至少 1 条标注
4. `样本 D：资源启停样本`
   - 至少 1 个已停用附件或视频
   - 至少 1 条已停用视频标注
5. `样本 E：长文本样本`
   - 外链 URL 超过 120 字符
   - 文件名超过 80 字符
   - 标注内容超过 100 字符

### 3.2 数据库取证要求

每次回归至少准备以下 SQL 查询：

```sql
SELECT id, flow_code, process_type, current_node_status, current_node_label
FROM gxpublish_brain.brain_manuscript_review
WHERE id = ?;

SELECT id, review_id, file_name, file_size, create_by, create_time, enabled
FROM gxpublish_brain.brain_manuscript_review_attachment
WHERE review_id = ?
ORDER BY create_time, id;
```

## 5. 详细测试用例

### TC-R9-01 作者字段必填前移

- 测试目标：确认前端与后端对“作者必填”口径一致。
- 使用账号：`mr_initiator`
- 前置条件：进入新增页。
- 操作步骤：
  1. 登录系统。
  2. 进入 `/manuscript/review/form?mode=create`。
  3. 填写标题、媒体栏目、正文、流程类型。
  4. 作者留空。
  5. 点击主按钮提交。
- 预期结果：
  1. 作者字段显示必填标识。
  2. 作者字段就地出现校验提示，不等待后端返回。
  3. 请求不应发出，或发出前即被前端阻止。
- 取证要求：
  1. 浏览器截图：作者字段错误提示。
  2. Network：确认未发起提交请求，或请求被前端拦截。

### TC-R9-02 多视频切换后，新增标注当前视频实时联动

- 测试目标：避免标注落到错误视频。
- 使用账号：`mr_approver_l1` 或具编辑权账号
- 前置条件：样本 C 存在，详情页至少有 2 个有效视频。
- 操作步骤：
  1. 打开样本 C 详情页。
  2. 观察当前激活视频为视频 A。
  3. 点击上方切换到视频 B。
  4. 查看“新增视频标注”区域中的“当前视频”下拉值。
- 预期结果：
  1. 下拉值自动切到视频 B。
  2. 不再保留视频 A。
- 取证要求：
  1. 浏览器截图：切换前后两个状态。

### TC-R9-03 修改页不得再改流程类型

- 测试目标：确认创建后流程类型冻结。
- 使用账号：`mr_initiator` 或允许修改的退回发起人
- 前置条件：样本 B 可进入修改页。
- 操作步骤：
  1. 从详情页进入修改页。
  2. 观察“流程类型”控件。
  3. 尝试切换流程类型。
- 预期结果：
  1. 流程类型为只读或禁用态。
  2. 页面上无法修改该值。
- 取证要求：
  1. 浏览器截图：流程类型只读态。

### TC-R9-04 绕过前端强行改流程类型，后端应拒绝或忽略

- 测试目标：确认后端防御式冻结生效。
- 使用账号：具编辑权账号
- 前置条件：样本 B 已知当前 `flow_code` 与 `process_type`。
- 操作步骤：
  1. 直接构造 `PUT /workflow/manuscript-review` 请求。
  2. 将 `processType` 改成与原值不同。
  3. 提交保存。
  4. 查询主表。
- 预期结果：
  1. 请求被拒绝，或后端忽略非法变更。
  2. `brain_manuscript_review.flow_code` 不变。
  3. `process_type` 不变。
- 取证要求：
  1. 接口响应。
  2. 数据库查询结果。

### TC-R9-05 大文件上传显示进度且提交按钮阻断

- 测试目标：确认用户能感知上传进行中，且不会误提交。
- 使用账号：`mr_initiator`
- 前置条件：准备一个较大的 PDF 或视频文件，上传过程可观察。
- 操作步骤：
  1. 进入新增页。
  2. 上传大文件。
  3. 在上传过程中观察页面。
  4. 尝试点击主提交按钮。
- 预期结果：
  1. 页面显示上传进度。
  2. 主提交按钮在上传完成前禁用。
  3. 用户不会误以为上传失败。
- 取证要求：
  1. 浏览器录屏或两张截图。
  2. Network 上传请求状态。

### TC-R9-06 详情/审批/修改页不再展示技术链接

- 测试目标：确认业务用户看不到内部预览地址。
- 使用账号：
  - `mr_initiator` 查看详情
  - `mr_approver_l1` 查看审批页
- 前置条件：样本 B/C 存在附件、视频、外链。
- 操作步骤：
  1. 打开详情页。
  2. 打开审批页。
  3. 打开修改页的已入库资源区。
  4. 检查附件与视频的说明文本。
- 预期结果：
  1. 附件/视频区域不显示 `/workflow/manuscript-review/resource/...` 之类技术地址。
  2. 外链仍可显示真实 URL。
- 取证要求：
  1. 三个页面截图。
  2. 接口返回字段截图，确认 `resourceUrl` 只用于动作，不用于备注展示。

### TC-R9-07 资源项显示操作人、操作时间、文件大小

- 测试目标：确认四类资源展示项的元信息补齐。
- 使用账号：任一可查看详情用户

  1. 样本 B/C 中有附件、视频、外链、视频标注。
  2. 附件表 `file_size/create_by/create_time` 已有值。
- 操作步骤：
  1. 打开详情页。
  2. 分别查看附件、视频、外链、视频标注区。
- 预期结果：
  1. 四类资源都显示“操作人、操作时间”。
  2. 附件与视频额外显示“文件大小（MB）”。
  3. 口径使用当前有效项的创建人/创建时间。
- 取证要求：
  1. 浏览器截图。
  2. `getDetail` 接口返回字段。
  3. 数据库附件表数据比对。

### TC-R9-08 资源区固定高度，内容超长时区块内滚动

- 测试目标：确认长文本不会再拉高整个布局。
- 使用账号：任一可查看详情用户
- 前置条件：样本 E 存在。
- 操作步骤：
  1. 打开详情页。
  2. 观察四个资源区高度。
  3. 将页面滚动到资源区，检查区块内部滚动条。
- 预期结果：
  1. 四个资源区高度保持稳定。
  2. 长文件名、长链接、长标注不会把卡片高度无限拉高。
  3. 超出内容在卡片内滚动。
- 取证要求：
  1. 浏览器整页截图。

### TC-R9-09 单条外链样式不再异常放大

- 测试目标：确认只有 1 条外链时不再出现按钮/条目被拉大。
- 使用账号：任一可查看详情用户
- 前置条件：准备一个只有 1 条外链的样本，以及一个有 2 条外链的样本。
- 操作步骤：
  1. 分别打开两个样本详情页。
  2. 对比外链区样式。
- 预期结果：
  1. 单条外链样式与多条外链保持同一视觉规则。
  2. 按钮尺寸、卡片高度无异常放大。
- 取证要求：
  1. 两组对比截图。

### TC-R9-10 视频标注启用后，旧停用历史上的启用按钮自动隐藏

- 测试目标：确认启用动作不会在旧历史项上重复暴露。
- 使用账号：具编辑权用户
- 前置条件：样本 D 至少有一条已停用视频标注。
- 操作步骤：
  1. 在历史区点击该标注的“启用”。
  2. 启用成功后刷新详情。
  3. 再次回到原停用历史项。
- 预期结果：
  1. 标注恢复到当前有效标注区。
  2. 原停用历史项上的“启用”按钮消失。
- 取证要求：
  1. 启用前后截图。
  2. 历史区截图。

### TC-R9-11 视频标注时间展示口径统一

### TC-R9-12 新增视频标注校验提示就近显示

### TC-R9-13 主动退出登录后，不再把前一用户路由带给下一用户

- 测试目标：确认跨用户串页问题被修复。
- 使用账号：
  - 第 1 个用户：`mr_initiator`
  - 第 2 个用户：`mr_observer`
- 前置条件：
  1. `mr_initiator` 可进入新增页。
  2. `mr_observer` 无审校新增权限。
- 操作步骤：
  1. 用 `mr_initiator` 登录。
  2. 打开 `/manuscript/review/form?mode=create`。
  3. 主动退出登录。
  4. 用 `mr_observer` 登录。
- 预期结果：
  1. `mr_observer` 登录后默认进入首页 `/index`。
  2. 不会被带回 `/manuscript/review/form?mode=create`。
  3. 不出现 404 或无权限页回跳。
- 取证要求：
  1. 浏览器录屏或连续截图。
  2. 登录 URL 截图，确认退出时未携带旧 `redirect`。

### TC-R9-14 未登录被拦截后，正常 redirect 机制仍保留

- 取证要求：
  1. 浏览器录屏。
