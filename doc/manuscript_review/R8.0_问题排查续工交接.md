## 3. 当前已锁定的根因

### 3.1 问题 1：新增/修改后上传附件再点删除，报没有权限

- 已确认根因：
  - 表单暂存删除走的是全局 OSS 删除接口：`DELETE /resource/oss/{ossId}`
  - 前端入口：`plus-ui-ts/src/api/manuscript-review/index.ts:61-65`
  - 页面动作：`plus-ui-ts/src/views/manuscript-review/form.vue:423-430`
  - 后端接口：`Brain/brain-modules/brain-system/src/main/java/com/gxpublish/brain/system/controller/system/SysOssController.java:97-103`
  - 该接口受 `system:oss:remove` 权限保护：`SysOssController.java:97`
- 结论：
  - 这是权限设计问题，不是前端按钮误触。
  - manuscript-review 发起人/审批人没有全局 OSS 删除权限时，浏览器点击删除就会报“没有权限”。
- 建议修复方向：
  - 不要给审校角色直接发全局 `system:oss:remove`
  - 新增 manuscript-review 自有“暂存资源删除”接口，按当前用户 + 当前表单/流程上下文校验后删除
- 影响面：
  - 后端：manuscript-review controller/service + 可能需要补一层“只删未入库临时资源”的校验
  - 前端：`form.vue` 删除动作改调新接口

### 3.2 问题 3：审校台账和我的待办/已办对不上，且台账先全量查到内存再分页

- 已确认根因 A：台账后端确实是“全量加载 -> Java 内存过滤 -> Java 内存分页”
  - 代码位置：`ManuscriptReviewReadableService.listLedger`
  - 关键实现：`Brain/brain-modules/brain-manuscript-review/src/main/java/com/gxpublish/brain/manuscript/review/service/ManuscriptReviewReadableService.java:124-145`
- 已确认根因 B：审校台账与我的待办/已办/我发起的三套页面，当前根本不是同一个数据源
  - 审校台账：`/workflow/manuscript-review/list`
    - 前端：`plus-ui-ts/src/views/manuscript-review/index.vue:183-190`
    - 后端：`ManuscriptReviewReadableApiController.java:27-31`
  - 我发起的：走 `pageByCurrent`
    - `plus-ui-ts/src/views/manuscript-review/my-document.vue:56-58,83-88`
  - 我的待办：走 `pageByTaskWait`
    - `plus-ui-ts/src/views/manuscript-review/task-waiting.vue:49-50,73-78`
  - 我的已办：走 `pageByTaskFinish`
    - `plus-ui-ts/src/views/manuscript-review/task-finish.vue:53-54,74-79`
- 已确认根因 C：当前台账可见性规则不是“发起人=我发起；审批人=待办+已办；多角色=并集”
  - 当前实现是：
    - 发起人可见
    - 当前审批人可见
    - 历史参与人可见
  - 代码：`ManuscriptReviewReadableService.java:548-559`
- 结论：
  - 当前台账口径和您描述的需求口径不是一回事。
  - 即使不谈分页性能，三套页面也会天然漂移。
- 建议修复方向：
  - 重新定义“审校台账”后端查询口径：
    - 发起人：等价于“我发起的”
    - 审批人：等价于“我的待办 ∪ 我的已办”
    - 多角色：等价于多个角色条目的并集
  - 用数据库完成筛选、去重、排序、分页，不再把所有记录拖到内存
- 影响面：
  - 后端：`ManuscriptReviewReadableService`、新增 mapper SQL、必要时补 VO/查询对象
  - 前端：台账页字段可能少量联动，但主改动应在后端

### 3.3 问题 4：PDF 在详情页点预览，新标签页 access denied

- 已确认根因：
  - 附件详情返回的 `resourceUrl` 直接取 `attachment.fileUrl`
  - 代码：`ManuscriptReviewReadableService.java:490-499`
  - 详情页“预览”动作直接 `window.open(item.resourceUrl)`
  - 代码：`plus-ui-ts/src/views/manuscript-review/detail-page-shell.vue:437-438,597-599`
  - 目前只有视频做了“可读 URL / 预签名 URL”转换
  - 代码：`ManuscriptReviewReadableService.java:789-829`
  - 全局 OSS 下载接口又受权限保护
  - `SysOssController.java:86-103`
- 结论：
  - PDF/普通附件预览当前走的是原始 OSS 地址；如果底层桶是私有或地址不可匿名访问，就会新标签页 `access denied`
- 建议修复方向：
  - 附件和视频统一走“可读 URL”生成策略，不要只有视频做预签名
  - 或者改成模块自有 preview/download 中转接口
- 影响面：
  - 后端：`ManuscriptReviewReadableService` 的附件 `resourceUrl` 生成逻辑
  - 前端：若后端直接返回可读 URL，详情页动作逻辑可基本不改

### 3.4 问题 5：视频标注找不到新增入口，更别说删除

### 3.5 问题 6：停用后只能停用，不能再次启用

- 已确认根因：

  - 资源：

    - `disableAttachment` -> `919-930`

### 3.6 问题 7：退回历史看不到是谁在什么环节退回，其他历史也不够完整

- 已确认根因 B：审批/驳回 history 文案只写“某级审批通过/三级审批驳回”，没有统一包含“谁在什么环节做了什么”
