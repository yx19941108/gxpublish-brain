# R9.11 首页前端实现与最小验证记录 v01

## 1. 本轮目标

基于已定稿的首页高保真与 `R9.10` 评审口径，落地新的业务系统首页前端实现，并满足以下约束：

1. 保留原首页，不能直接覆盖丢失。
2. 首页业务模块只展示当前用户实际拥有菜单的模块。
3. 点击“点击进入”后必须进入对应已有菜单页面。
4. 左侧菜单高亮必须落到对应菜单项，不能停留在首页。
5. 严格复用现有菜单、现有路由、现有权限体系，不新增首页专属后端接口。

### 2.2 新首页实现

本轮已完成新首页主实现：

1. [index.vue](/home/kugua/dev/gxpublish-brain/plus-ui-ts/src/views/index.vue)

实现口径：

1. 首页结构按高保真收敛为 `品牌 Hero + 业务模块区`。
2. 桌面端采用四列卡片布局，移动端收敛为单列堆叠。
3. 文案、模块标题、按钮语义均对齐 `home-desktop.html / home-mobile.html / style.css` 与 `R9.10`。

### 2.3 首页模块配置与菜单过滤

本轮新增首页模块配置与菜单解析文件：

1. [index-home.modules.ts](/home/kugua/dev/gxpublish-brain/plus-ui-ts/src/views/index-home.modules.ts)

核心逻辑：

1. 首页预置四个模块配置，仅对应以下既有路由：
   - `/manuscript/review`
   - `/manuscript/review/my-document`
   - `/manuscript/review/task-waiting`
   - `/manuscript/review/task-finish`
2. 首页不直接读取按钮权限码，也不请求新接口。
3. 首页直接复用 `permissionStore.getSidebarRoutes()` 作为“当前用户实际可见菜单”的数据源。
4. 通过递归收集当前侧栏可见路由路径，只展示当前用户真实拥有的审校菜单模块。
5. 如果某个菜单不在当前 `sidebarRouters` 中，则首页不展示对应模块卡片。

这满足了“有什么菜单，就展示什么业务模块；没有的菜单不要展示”的要求。

### 2.4 点击进入与菜单高亮

本轮未新增任何首页专属跳转壳层，而是直接复用既有路由：

1. 首页按钮点击后执行 `router.push({ path })`，目标路径就是现有菜单路由路径。
2. 这些页面已经在 [plus-ui-ts/src/router/index.ts](/home/kugua/dev/gxpublish-brain/plus-ui-ts/src/router/index.ts) 中声明了既有直达路由。
3. 侧栏高亮继续复用现有 Sidebar 逻辑：
   - [plus-ui-ts/src/layout/components/Sidebar/index.vue](/home/kugua/dev/gxpublish-brain/plus-ui-ts/src/layout/components/Sidebar/index.vue)
4. 侧栏高亮判断规则仍是：
   - 优先读当前路由 `meta.activeMenu`
   - 否则回落到当前 `path`
5. `manuscript-review` 相关页面本来就已经配置了对应的 `meta.activeMenu`，因此从首页跳转后，左侧菜单会落到对应业务菜单，不会继续停在首页。

## 5. 剩余风险

1. 虽然静态测试与生产构建已通过，但尚未在真实登录态下逐个账号验证“首页显示模块集合”和“左侧菜单高亮”最终运行态。
2. 当前首页模块展示严格依赖 `sidebarRouters`。如果后续后端菜单返回路径口径变化，首页可见模块集合会随之变化。
3. 备份文件 `index-legacy-backup.vue` 会进入前端构建产物，但不参与当前路由渲染；这符合“保留原首页备份”的目标，运行风险较低。
