# R7.10_正式测试问题记录-审批通过后原审批人被带回无权详情页

## 1. 这是什么问题

在正式全量测试里，审批人对样本完成审批提交后，前端没有停留在可继续操作的页面，也没有跳去“我的已办”或其他可承接成功态的页面，而是自动跳回该流程的详情页：

- `/manuscript/review/detail?reviewId=2037413044715327490`

但此时刚完成审批的账号对该流程已经无查看权限，详情接口真实返回：

- `code = 500`
- `msg = 当前用户无权查看该流程`

最终浏览器页面呈现为：

- `详情数据加载失败，请稍后重试。`

这不是审批未成功，而是审批成功后的前端回跳目标与当前权限状态不匹配。

## 2. 我是怎么复现出来的

1. 确认运行环境恢复：
   - `http://127.0.0.1:9999` -> `200`
   - `http://127.0.0.1:9888` -> `200`
2. 使用审批账号登录，例如：
   - `mr_approver_l1`
   - `mr_approver_l2`
   - `mr_approver_l3`
3. 打开普通 fresh 样本详情页：
   - `reviewId = 2037413044715327490`
4. 点击 `去审批` 进入审批页。
5. 点击 `审批办理`，填写审批意见并提交。
6. 点击 `提交`，并在确认弹窗点击 `确定`。
7. 观察审批后页面跳转与加载结果。

## 3. 实际看到的结果

浏览器层真实结果：

1. 审批办理弹窗正常拉起。
2. 提交确认弹窗正常拉起。
3. 提交后页面自动跳回详情页。
4. 详情页没有展示二级审批后的正常摘要，而是出现：
   - `详情数据加载失败，请稍后重试。`
5. 页面动作栏只剩：
   - `返回`

## 4. 接口层真实结果

同一轮浏览器操作里，关键接口真实返回如下：

1. 审批提交接口：
   - `POST /dev-api/workflow/task/completeTask`
   - 返回：
     - `code = 200`
     - `msg = 操作成功`

2. 审批后详情读取接口：
   - `GET /dev-api/workflow/manuscript-review/2037413044715327490`
   - 返回：
     - `code = 500`
     - `msg = 当前用户无权查看该流程`

这说明“审批提交成功”和“审批后回跳详情失败”是两个连续但不同层次的事实，不能混为一个“审批失败”。

## 6. 我对问题的判断

当前更符合事实的判断是：

1. 审批业务动作本身已成功。
2. 审批成功后，前端把刚完成审批的原审批人带回了一个他已无权读取的详情页。
3. 页面未对这种“审批成功但当前账号不再有详情权限”的场景做正确承接，因此用户最终看到的是误导性的失败页。
4. 该问题已不只影响一级审批，而是已在普通链路的一级、二级、三级审批后连续复现。

这类问题会直接影响：

- 审批成功后的用户闭环体验
- 正式测试中“审批通过后页面回跳是否正确”的相关用例
- 后续“我的已办 / 查看 / 办理”口径核对

## 7. 建议怎么处理

建议按下面顺序处理：

1. 先定审批成功后的页面承接口径：
   - 回详情页
   - 回我的已办
   - 或停在审批页并提示成功
2. 如果审批后原审批人本就无详情权限：
   - 前端不应继续跳详情页
   - 或应跳到可读的已办承载页
3. 修完后复测：
   - 同一条普通链路 fresh 样本重跑一级、二级、三级审批
   - 核对审批提交成功后页面是否落到正确承载页
   - 再核对“我的已办”是否能正确看到并查看该流程

## 8. 当前结论

这个问题已经具备浏览器、接口、MySQL 三层证据，且已在普通链路一级、二级、三级审批后连续复现：

- 是否存在问题：是
- 是否已修复：否
- 是否阻断继续推进：不阻断普通链路继续由 `mr_approver_l2` / `mr_approver_l3` 推进，但会影响审批完成后的页面体验与后续已办口径核对

游工提出修改方式：修改保存跳回详情页，审批完成后跳回列表页，审批页点击返回跳回入口页（待办进入跳待办列表，详情页进入跳详情），修改详情页点击返回同审批页。
