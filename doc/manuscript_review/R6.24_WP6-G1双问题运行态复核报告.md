## 已确认事实

1. 问题A：持证发起人“自动跳过一级审批”在业务层与流程引擎层不一致。
- 代码层存在 skip 判定与 history 记录：
  - `SubmissionRoute.skipLevelOne()` 生效时会写 `currentNodeLabel=待二级审批` 并写 `SKIP_LEVEL_1`。
  - 参考：`Brain/brain-modules/brain-manuscript-review/src/main/java/com/gxpublish/brain/manuscript/review/service/ManuscriptReviewService.java`。
- runtime fresh 证据（reviewId=`2036739192533635074`）：
  - `brain_manuscript_review.current_node_label=三级审批`（该单后续已走过 L1/L2）
  - `brain_manuscript_review_history` 含 `SKIP_LEVEL_1`
  - 但 flow task 在该单创建后真实先出现的是 `first-review-node`（一级审批待办），并分配给一级审批人（`64001/64006`）。

2. 问题B：`brain_manuscript_review_history` 未写入一级/二级审批通过记录。
- 对同一 fresh 样本 `reviewId=2036739192533635074`：
  - 已执行 `mr_approver_l1` 的 `completeTask`（HTTP 200, code 200）
  - 已执行 `mr_approver_l2` 的 `completeTask`（HTTP 200, code 200）
  - 主表节点已推进到 `三级审批`
  - 但 history 仍仅有：`CREATE / RESOURCE_ADD / SUBMIT / SKIP_LEVEL_1`
  - 根据约束，创建并提交流程仅应该出现CREATE，而不是CREATE / RESOURCE_ADD / SUBMIT三条。
  - 未出现 `APPROVE`（一级通过、二级通过）记录。
