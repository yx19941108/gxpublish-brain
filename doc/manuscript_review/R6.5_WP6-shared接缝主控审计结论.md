## 2. 关键原因

- 后端 shared 接缝本身已完成最小整改：
  - shared controller 已统一到 `/workflow/manuscript-review/**`
  - shared list/detail 已输出冻结契约要求的新字段组，包括 `submitDepartment`、`businessStatus`、`currentNodeCode`、`attachmentList`、`externalLinkList`、`videoList`、`videoMarkList`、`timelineItems`、`permissionMatrix`
- 当前真实页面载体尚未完成 shared 新契约切换：
  - `plus-ui-ts/src/views/manuscript-review/index.vue` 仍直连旧 `/manuscript-review/readable/ledger`
  - `plus-ui-ts/src/views/manuscript-review/detail.vue` 仍直连旧 `/manuscript-review/readable/detail`
  - 列表页仍直接消费 `mediaChannelLabel`、`flowStatusLabel`、`latestUpdatedAt` 等旧字段名
- shared adapter 仍保留旧语义兼容口：
  - `plus-ui-ts/src/views/manuscript-review/detail.contract.ts` 仍兼容 `timeline/history/attachments/fileUrl/mediaChannelLabel/flowStatusLabel/submitterDeptName` 等旧形态
  - `ManuscriptReviewLedgerQueryRequest` 仍接受 `processTypeLabel/flowStatusLabel/currentNodeLabel` 旧别名写法
- 因此当前仓库状态更准确的表达是：
  - `WP6 shared 接缝最小整改已绿`
  - `repo 级冻结口径尚未闭环`
  - `R7` 进入条件尚未满足

## 3. 是否发现旧失败实现污染

- 结论：`发现残留级旧语义兼容口，但未发现旧失败实现重新主导 shared 主链`
- 已确认未发现：
  - `brain-editorial` 旧线引用
  - `plus-ui-ts/src/views/editorial/**` 或 `src/api/editorial/**` 引用
  - 以 `brain-manuscript-review` 旧 controller/service 语义直接反推冻结契约
- 已发现的残留级旧语义兼容口：
  - 页面真实请求仍落在旧 readable 路径
  - shared adapter 仍保留旧字段名与旧结构兼容分支
  - request DTO 仍保留旧查询别名映射
- 裁定：
  - 这属于“旧兼容残口未清干净”
  - 还不能写成“已完全清除旧失败实现影响”

## 4. 是否破坏 shared / private 边界

- 结论：`后端边界较 R6.3 已收口，但前端 shared 接缝仍未闭合`
- 后端侧：
  - 本轮未见继续打穿 shared / private 边界
  - shared controller 已接入 private service，较 `R6.3` 的 stub 状态明显改善
- 前端侧：
  - shared API 已建立 `src/api/manuscript-review/**`
  - 但真实页面尚未消费该 shared API，而是继续绕过 shared 层直连旧 readable 路径
- 裁定：
  - 不能再判定为 `R6.3` 意义上的“后端 shared/private 断裂”
  - 但仍不能判定为“前后端 shared 接缝已完成 repo 级闭环”
