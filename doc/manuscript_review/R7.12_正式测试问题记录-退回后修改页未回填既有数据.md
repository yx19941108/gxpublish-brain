# R7.12_正式测试问题记录-退回后修改页未回填既有数据

## 1. 这是什么问题

在正式全量测试里，发起人拿到“已退回 / 待发起人处理”的样本后，从详情页点击“修改”进入：

- `/manuscript/review/form?reviewId=2037437986613764098&mode=edit`

此时后端详情接口真实返回：

- `GET /dev-api/workflow/manuscript-review/2037437986613764098`
- `code = 200`
- `msg = 操作成功`
- `data` 内含完整主表字段、外链列表、时间线、`permissionMatrix.canEdit = true`

但浏览器实际进入修改页后，表单没有把既有数据回填出来：

1. `流程类型` 显示为 `请选择流程类型`
2. `外部稿件号 / 标题 / 媒体栏目 / 作者 / 说明 / 正文` 全为空
3. 外链录入区为空
4. `当前已入库资源` 显示 `暂无已入库资源`

这不是“详情无权”问题，也不是“修改保存失败”问题，而是“修改页承接已有数据失败”。

## 2. 我是怎么复现出来的

1. 创建 fresh 普通样本：
   - `reviewId = 2037437986613764098`
2. 使用 `mr_approver_l1` 对该样本执行一级退回：
   - `POST /dev-api/workflow/task/backProcess`
   - `code = 200`
3. MySQL 已真实进入：
   - `flow_status_label = 已退回`
   - `current_node_label = 待发起人处理`
   - `current_node_status = RETURN_TO_INITIATOR`
4. 使用 `mr_initiator` 打开详情页：
   - 动作栏真实显示 `修改 / 再次提交 / 返回`
5. 点击 `修改` 进入 edit 页，观察表单加载结果

## 3. 实际看到的结果

### 3.1 浏览器层

详情页进入 edit 页后，页面标题与路由都正确：

- 页面标题：`修改审校单`
- 路由：`/manuscript/review/form?reviewId=2037437986613764098&mode=edit`

但页面表单区没有回填任何既有业务数据，关键输入框均为空。

补充证据：

- 截图：`.agent-temp/mr_review_branch1_return_edit_empty_20260327_1601.png`

### 3.2 接口层

同一浏览器会话下，edit 页真实拉取到的详情接口响应体包含：

1. 主表字段：
   - `processType = AUDIT`
   - `title = 正式测试-mr_initiator-新增提交-20260327155338`
   - `mediaChannel = 新华社/正式测试频道-20260327155338`
   - `authorName = 张三、李四`
   - `remark = 正式测试新增并提交-20260327155338`
   - `contentBody = 正式测试正文-20260327155338`
2. 资源字段：
   - `externalLinkList` 含 1 条已入库外链
3. 权限字段：
   - `permissionMatrix.canEdit = true`
   - `permissionMatrix.canResubmit = true`

说明 edit 页并不是“没拿到数据”，而是“拿到数据但没有正确承接到表单”。

## 4. 影响

这个问题会直接影响以下正式测试口径：

1. `退回后修改保存`
2. `退回后再次提交前的修改承接`
3. edit 页“已入库资源展示区”与“本次新增资源区”的边界校验

业务风险是：

1. 发起人会以为原数据丢失
2. 修改时需要手工重填全部必填字段
3. 容易引入误改或漏改
4. 会污染“退回修改保存”用例本身的判断链

## 5. 当前判断

当前更符合事实的判断是：

1. 退回动作本身已成功
2. 发起人详情页权限承接也成功
3. 新问题发生在“详情 -> 修改页”的 edit 承接层
4. 这是新的问题类型，应单独开问题单

## 6. 建议处理

建议按下面顺序处理：

1. 先核对 edit 页使用的详情映射字段，确认是否没有把：
   - `processType`
   - `externalManuscriptCode`
   - `title`
   - `mediaChannel`
   - `authorName`
   - `remark`
   - `contentBody`
   - `externalLinkList`
   正确写入 form state
2. 再核对“已入库资源展示区”是否错误依赖了别的字段名
3. 修复后至少复测：
   - 被退回发起人点击 `修改`
   - edit 页既有字段回填
   - 保存后仍不推 BPM
   - 再次提交后重新进入一级审批

## 7. 当前结论

- 是否存在问题：是
- 是否已修复：否
- 是否阻塞后续分支测试：部分阻塞
