游工，以下输出只基于 PRD + R1 + R2 + R3 + R4 + R4.5，并以 PRD > R4.5 > R4 > R3 > R2/R1 为冲突裁决顺序。

  一、测试范围总览

  1. 本轮测试计划覆盖的范围
     覆盖一期已定稿的业务规则、流程规则、权限矩阵、资源生命周期、视频与标注、时间输入与归一化、列表页、详情页、接口契
     约、数据展示与脱敏、负向拦截、验收回归。
  2. 本轮不覆盖的范围
     不覆盖草稿、删除、回收站/恢复、会签/并行审批/加签/减签/转办、动态审批层级、稿件主数据/媒体主数据对接、Office 在线预
     览、外链联网可达性探测；不覆盖旧失败实现兼容；不覆盖未在输入材料中定稿的扩展能力。
  3. 本轮测试计划的目标

  - 支撑第6轮后端最小闭环：先压实主单、流程、权限、资源、时间校验、详情读模型与时间线。
  - 支撑第7轮前端最小闭环：确保列表、详情、资源区、视频区、动作分流与脱敏展示不偏口径。
  - 支撑第8轮补全与联调验收：把接口、页面、流程、资源历史、脱敏与异常拦截串成可回归验收集。

  二、测试分层

  1. 领域规则测试：验证字段业务规则、唯一性、长度、格式、基础约束。重要性：这是后端 DTO/BO/Service 校验与前端表单校验的
     共同基线，做错会引发全链路返工。
  2. 流程规则测试：验证普通流、持证跳级、退回重提、撤销、驳回、状态/节点同步。重要性：这是第6轮后端最小闭环的核心。
  3. 权限与动作矩阵测试：验证谁能看、谁能改、谁能去审批、谁只能读。重要性：这是详情页动作中枢和后端 permissionMatrix 的
     唯一依据。
  4. 资源生命周期测试：验证附件/外链/视频/标注的追加、停用、有效态与历史态。重要性：这是“当前有效资源 + 历史可追溯”口径
     的核心。
  5. 视频与标注测试：验证多视频、单播放器、在线播放边界、标注展示与跳转。重要性：这是一期最明显的业务差异点。
  6. 时间输入与归一化测试：验证时间录入格式、归一化与拦截。重要性：这是标注能力能否稳定落地的硬门槛。
  7. 列表页测试：验证排序、搜索、列展示、详情入口。重要性：这是业务台账的入口页，不允许动作越界。
  8. 详情页测试：验证状态摘要、基本信息、正文、资源区、时间线、动作分流。重要性：这是一期动作中枢。
  9. 接口集成测试：验证接口名、入参、出参、读模型、权限矩阵、动作边界。重要性：这是第6轮后端和第7轮前端对接的契约层。
  10. 数据展示与脱敏测试：验证不暴露主键、账号、内部字段、原始码值。重要性：这是 PRD 明确要求，且最容易被实现层无意破
     坏。
  11. 负向/异常测试：验证配置缺失、越权、非法输入、非法状态、资源异常。重要性：这是防止闭环“看起来能跑、实际不可控”的关
     键。
  12. 验收回归测试：验证 PRD 一期验收标准的整链路回归。重要性：这是第8轮联调验收的最终落点。

  2. 页面行为最容易做错的点

  - 把列表做成多动作入口，违反“列表只保留详情”。

  - 直接显示LEVEL_*、roleKey、内部账号或技术主键。

  - 持证跳级、退回重提、撤销、驳回后的页面状态刷新。
  - 当前有效资源与历史时间线的聚合读模型。
  - 多视频切换与标注跳转对真实返回数据的适配。

  八、第8轮补全与联调关注点

  1. 第8轮最可能暴露的问题

  - 后端permissionMatrix与前端按钮矩阵不一致。
  - 时间线聚合项与资源生命周期状态不同步。
  - 流程状态、当前节点、页面展示文案三者不同步。
  - 多视频与标注在真实 OSS/元数据场景下出现边界错配。
  - 脱敏规则在列表、详情、时间线三个区域执行不一致。

  2. 最容易返工的3类缺陷

  - 契约返工：详情接口字段、permissionMatrix、读模型字段不稳。
  - 状态返工：持证跳级、退回重提、撤销、驳回后的业务状态/当前节点错误。
  - 展示返工：列表动作越界、详情脱敏缺漏、时间线文案不符合业务口径。

  3. 联调时优先回归的测试集

  - 流程主链路：FR-01、FR-02、FR-03、FR-04、FR-05、FR-06。
  - 权限与动作：PM-01、PM-02、PM-03、PM-05、PM-06。
  - 资源与时间：RL-01、RL-02、TN-03、TN-04、NE-05。
  - 页面与脱敏：LP-02、DP-03、DS-01、DS-02。
  - 验收整链路：AR-01、AR-02、AR-03、AR-04。

  九、风险与前置条件

  1. 仍需依赖的前置条件

  - 审批链轻量配置已按租户与流程类型就绪，且三级角色均有有效成员。
  - “持证发起人”专用角色已就绪且运行时可解析。
  - BPM 流程定义、待办办理页、表单路径跳转能力可用。
  - OSS 文件可读取，视频元数据识别能力可用。
  - 详情接口已按 R4.5 返回permissionMatrix与聚合读模型。

  2. 不满足前置条件时无法执行的测试

  - 没有审批链与角色成员，FR-01 至 FR-08、PM-01、API-03、NE-01 无法执行。
  - 没有“持证发起人”角色解析能力，FR-02、FR-03、NE-02 无法执行。
  - 没有 BPM 办理页或跳转参数，FR-07、PM-03、PM-06 无法执行。
  - 没有 OSS 与视频元数据，VM-01 至 VM-03、TN-01 至 TN-04、NE-04、NE-05 无法执行。
  - 详情接口未返回permissionMatrix，PM-02 至 PM-06、DP-01 至 DP-03 无法执行。

  3. 虽然已定稿但实现时仍最容易偏离的地方

  - 把审批链又做回独立业务表，而不是复用轻量配置。
  - 把审批角色配置依据写成内部标识，而不是roleKey。
  - 把权限布尔值散落到列表 VO 或前端本地推断，而不是只放详情permissionMatrix。
  - 把submitTime单字段复活，破坏firstSubmitTime/latestSubmitTime定稿口径。
  - 把停用做成删除，或把停用资源继续展示在当前有效资源区。
  - 把当前节点展示成代码态，而不是业务文案。
