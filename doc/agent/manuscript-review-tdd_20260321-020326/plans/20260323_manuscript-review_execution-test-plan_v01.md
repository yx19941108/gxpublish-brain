# Manuscript Review 一期详细测试方案 v01

## 1. 目标

本文档用于作为 `gxpublish-brain` clean-slate `manuscript_review` 研发线后续执行阶段的统一测试指标。

本方案的目标不是只证明一条 happy path，而是建立一套覆盖 PRD 一期验收要求的完整测试矩阵，用于约束：

1. 角色与可见性
2. 表单字段与编号规则
3. 提交、再次提交、修改、撤销、退回、驳回、审批分流
4. 台账、详情、BPM 待办/已办/发起一致性
5. 统一时间线历史
6. 附件、外链、视频、标注的生命周期与展示
7. 业务可读性与技术值泄露拦截

## 2. 需求真源与执行指标

### 2.1 唯一需求真源

- `doc/manuscript_review/product/20260321_manuscript-review_product-requirements_v01.md`

### 2.2 当前执行阶段必须同时对齐的指标文档

### 2.3 强约束

1. 这是 clean-slate `manuscript_review` 线，旧 `brain-editorial` 实现、页面、API、SQL 一律不得作为需求或兼容基线。
2. 后续执行阶段 controller 只负责编排、调度、监控、汇总，不直接越权执行真实 apply、真实 HTTP、浏览器操作，除非游工再次明确批准。
3. 不得把“可测试阶段”误报成“真实 HTTP / 真实 BPM / 浏览器联调 / 运行时闭环已通过”。
4. 所有 UI、API、历史文案必须业务可读，不得直出数据库 ID、账号、`roleKey`、`permission flag`、原始枚举码。
5. `reviewId` 仅允许用于隐式定位，不允许作为对业务用户的展示字段。

## 4. 范围与不纳入范围

### 4.1 本方案纳入范围

1. 一期 PRD 全量业务范围
2. PRD 第十四章 12 条验收标准
3. 负向约束：
   - 无草稿
   - 无删除
   - 无回收站
   - 无恢复
   - 无会签/并行审批
   - 无认领步骤
   - 无技术值泄露

1. 旧 editorial 兼容回归
2. 草稿、删除、回收站、恢复
3. 会签、并行审批、认领、转办等复杂审批形态
4. 动态审批层级
5. Office 页内在线预览
6. 外链联网可达性探测
7. 未经授权的 controller 本地代执行

## 10. 放行标准

1. 不能把静态验证、单测通过或 SQL 已 apply 误报成“一期已通过验收”。
2. 只有 A-H 组中所有必测条款闭环后，才允许宣称一期运行时验收通过。
3. 任一 blocker 未解除时，只能输出：
   - 已确认
   - blocker
   - 当前可执行范围
   - 待补实现/待补数据

## 11. 执行建议

1. 先执行补充 SQL，补齐角色矩阵。
2. 再按 `P1 -> P2 -> P3 -> P4 -> P5` 顺序推进。
3. 每一阶段单独出报告，不混写。
4. 后续所有 controller/worker 工作都必须回看本方案与 PRD。
