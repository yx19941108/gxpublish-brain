## Context

本仓库基于 RuoYi-Vue-Plus 派生架构：后端为 Spring Boot 3.5.x、JDK 17、MyBatis-Plus、Sa-Token、Warm-Flow，前端为 Vue 3、TypeScript、Vite 6、Element Plus，并已包含 ECharts。现有 `brain-workflow` 提供流程能力，`brain-manuscript-review` 是已接入工作流的具体业务模块。

本 change 只设计通用进度管理能力，不绑定出版稿件、选题、审校或研发缺陷等具体业务对象。后续业务若需要接入，应通过扩展关联能力挂接，而不是污染核心进度模型。

## Goals / Non-Goals

**Goals:**

- 新增通用进度管理模块，支持任何业务用项目化方式管理进展。
- 支持多层级项目树，项目树一期最多 3 层。
- 支持任意项目节点维护自身阶段、里程碑和任务。
- 支持阶段作为任务业务描述维度，避免阶段承担进度计算节点职责。
- 支持任务父子层级、任务权重、阻塞、优先级、取消/作废、逻辑删除和操作记录。
- 支持进度驾驶舱、项目管理、我的任务、风险与阻塞等查看和处理入口。
- 预留后续审批、业务关联、需求/缺陷/版本等扩展位。

**Non-Goals:**

- 一期不做完整禅道替代，不实现产品、需求、缺陷、测试、版本、迭代等研发管理对象。
- 一期不接 Warm-Flow 审批。
- 一期不强制绑定任何具体业务对象。
- 一期不以 Kanban 拖拽或甘特图作为主视图。
- 一期不做自由评论；只做系统自动生成的操作记录。

## Decisions

### 1. 独立业务模块

后端新增独立 `brain-progress` 模块，前端新增独立 `api/progress` 和 `views/progress`。这样可以保持通用进度能力与审校、系统、工作流等模块解耦。

备选方案是把功能放进 `brain-system` 或 `brain-workflow`，但会混淆系统基础能力、流程能力和业务进度能力的边界。

### 2. 通用模型，不直接绑定业务

核心项目、阶段、里程碑、任务表不保存具体业务模块语义。后续如需绑定稿件、选题、需求、缺陷、版本等对象，建议通过 `brain_progress_relation` 一类扩展关联表实现。

### 3. 多层级项目树

使用同一张项目表承载主项目、子项目、子系统、子模块，通过 `parent_id`、`ancestors/path`、`level` 和 `sort_order` 表达层级。`parent_id = 0` 表示顶级项目。

项目树一期最多 3 层：

- 第 1 层：顶级项目。
- 第 2 层：子项目/子系统。
- 第 3 层：子模块/专项。

超过 3 层的拆分，不继续建项目节点，应转为阶段、里程碑或父子任务表达。任意项目节点都允许创建自身阶段和任务。

### 4. 项目编号

项目编号由后端生成，前端只读展示，创建后不随项目名称变化，不支持编辑。

| 层级 | 生成规则 | 示例 |
|---|---|---|
| 顶级项目 | `XM` + 创建日期 `yyyyMMdd` + 当日三位流水 | `XM20260608001` |
| 二级项目 | 上级项目编号 + `-` + 同父级两位流水 | `XM20260608001-01` |
| 三级项目 | 上级项目编号 + `-` + 同父级两位流水 | `XM20260608001-01-01` |

暂不支持移动项目父级，避免破坏编号层级语义。

### 5. 阶段语义

阶段是当前项目节点下任务的业务描述维度和管理分组，不是进度计算单元。

阶段用于表达项目节点内的一段计划周期或工作分组，例如需求梳理、开发实施、联调验收。阶段只在所属项目节点内生效，不跨项目共享，不继承父项目阶段。子项目可以维护自己的阶段，任务只能选择当前项目节点下的阶段。

阶段不填报人工进度，不设置权重，不作为项目进度分母项。如果页面展示阶段进度，该值仅作为阶段列表展示值，由阶段下计入进度任务派生，不参与上卷计算。

阶段不做完整生命周期，只保留启用/已作废两态。阶段有关联任务或未作废里程碑时禁止作废；作废成功后不可再被新任务选择，也不可再被新里程碑作为关联阶段选择。阶段作废不影响任务状态、任务进度、项目进度；作废需要原因和二次确认，并记录操作记录。

### 6. 阶段和里程碑分表

阶段表示项目节点内的任务分组或计划周期。里程碑表示项目关键时间节点，必须归属当前项目，可选关联当前项目下启用阶段。

任务可以挂阶段，也可以作为项目直属任务存在。里程碑不承载任务，不参与进度权重计算，只用于关键时间节点、风险和统计展示。

里程碑类型分为项目级和关联阶段。项目级里程碑不选择阶段；关联阶段里程碑必须选择当前项目下启用阶段。阶段作废时，如存在未作废里程碑关联该阶段，禁止作废，需要先将里程碑改为项目级或改到其他启用阶段。

### 7. 任务归属与父子任务

任务可以直接挂项目节点，也可以挂阶段。`stage_id = 0` 表示项目直属任务。任务允许父子结构，`parent_id = 0` 表示一级任务。

子任务必须归属同一项目节点。若子任务选择阶段，该阶段必须属于任务归属的同一项目节点。

### 8. 进度来源

只有叶子任务产生人工进度。父任务是汇总容器，不允许人工直接维护当前进度。

已修正口径：

- 阶段不参与项目进度计算，不作为项目进度分母项。
- 阶段下任务仍是任务；阶段只是这些任务的归属维度。
- 项目节点进度不再采用“直属子项目、直属阶段、直属任务统一汇总池”旧口径。
- 父子项目进度是否汇总、如何汇总，以及子项目是否设置权重，后续继续确认。
- 父任务进度来自计入进度的直接子任务；父任务本身不产生当前进度。
- 里程碑不承载任务，不参与进度权重计算。
- 叶子任务人工进度允许 `0` 到 `100` 的整数。

任务从叶子任务变为父任务时，应提示用户：新增子任务后，当前任务已填写的人工进度将由子任务汇总进度覆盖。用户确认后才能新增计入进度的子任务。任务重新变回无计入进度子任务的叶子任务时，当前进度恢复为该任务最后一次作为叶子任务时人工填报的进度。该内部保存值对用户透明，页面只展示一个当前进度。

### 9. 任务加权进度

权重是同一父任务下直接子任务之间的相对系数，不是百分比。

规则：

- 权重字段只允许非负整数。
- `weight = 0` 表示自动权重，正整数表示用户显式填写的相对权重。
- 有效权重只在计算和展示时派生，不回写到权重字段。
- 同级存在显式权重时，自动权重项的有效权重等于同级显式权重的平均值；该有效权重可为小数。
- 同级全部为自动权重时，各项等权计算。
- 父任务进度按 `子任务有效进度 * 子任务有效权重 / 同级有效权重总和` 加权求和。
- `include_progress = 不计入`、已取消、已作废、已逻辑删除的任务不进入进度分母，也不贡献进度。
- 新增计入进度的任务会扩大工作范围，可能导致父级进度下降；系统应记录操作记录并触发上级重算。

示例：同级任务权重为 `60`、`80`、`100` 时，总权重为 `240`，有效占比分别为 `60/240`、`80/240`、`100/240`。同级权重为 `20`、`30`、`10`、`0` 时，自动项有效权重为 `(20+30+10)/3 = 20`，总有效权重为 `80`。

### 10. 任务状态与进度

任务主状态为：未开始、进行中、已完成、已取消、已作废。

状态规则：

- 任务状态由有权限用户人工维护，进度变化不自动修改状态。
- 叶子任务状态为已完成时，在列表、统计和上级汇总中的有效进度按 `100%` 处理；该规则只适用于叶子任务。
- 父任务即使状态为已完成，仍展示子任务汇总进度，不因父任务状态强制覆盖为 `100%`。
- 父任务存在未完成的计入进度子任务时，禁止标记为已完成。
- 已完成父任务禁止新增子任务；如需新增子任务，用户应先将父任务改回非完成状态。
- 已完成任务允许继续编辑普通字段，关键字段变更应记录操作记录并触发必要的进度重算。
- 已取消任务可恢复为其他可编辑状态；进入已取消和从已取消恢复均要求填写原因，并记录到状态变更记录或操作记录中。
- 已作废为终态，不允许再编辑任务内容、进度、状态、权重、阻塞等。
- 进入已作废要求填写原因并二次确认。

取消、恢复和作废原因属于状态变更事件，不应覆盖为任务上的单一原因字段；任务详情应能查看完整状态流转历史。

### 11. 项目状态

项目状态相关操作先后置，等项目页面其他内容确认后，再通过操作全集和状态矩阵统一决定。已确认原则：

- 项目状态不放在新建项目表单中随手选择。
- 高影响项目操作，如完成、取消、归档、重新打开等，不放在左侧项目卡片区。
- 高影响项目操作需要原因、二次确认、权限校验、必要的下级校验和操作记录。

### 12. 阻塞

阻塞独立于主状态，表示当前执行风险，不进入项目、阶段、任务的生命周期状态机。

已确认规则：

- 阻塞信息独立于项目、阶段、任务主体信息保存，具体表结构和字段在概要设计阶段确定。
- 阻塞对象支持项目、阶段、任务。
- 阻塞类型为：外部依赖、内部协作、资源不足、决策待定、环境/系统问题、其他。
- 阻塞和解除阻塞均应记录操作记录。
- 项目和阶段页面应区分自身阻塞与下级阻塞。
- 阻塞不直接改变进度计算，只影响风险提示、筛选、统计和看板标识。

### 13. 人工风险与系统预警

人工风险等级为：正常、有风险、已偏离。

规则：

- 项目、阶段、任务三个层级均支持维护人工风险等级。
- 人工风险等级由有权限用户维护。
- 风险升高、风险降低、恢复正常和风险等级调整均要求填写原因，并记录操作记录。
- 下级风险不自动覆盖父级人工风险，只生成系统预警。

系统预警作为系统计算出的可解释标签，不覆盖人工风险等级。已确认的系统预警类型和口径：

- 已逾期：对象有计划完成时间，当前日期已超过计划完成时间，且对象未完成、未取消、未归档。
- 临近逾期：对象有计划完成时间，距离截止时间小于等于预警阈值，且对象未完成、未取消、未归档；默认阈值为 3 天，可后续配置。
- 存在阻塞：对象自身有未解除阻塞。
- 下级阻塞：对象下级存在未解除阻塞；适用于项目、阶段。
- 进度滞后：对象有计划开始和计划完成时间，计划时间进度明显超过当前进度；默认阈值为 20 个百分点。
- 下级风险：下级对象人工风险等级为有风险或已偏离；适用于项目、阶段。
- 里程碑风险：项目内存在已逾期或临近逾期但未完成的里程碑；适用于项目。关联阶段仅作为里程碑归属展示，不把里程碑风险变成阶段风险。

系统预警的数据来源、缓存、快照、冗余字段和定时任务频率属于概要设计范围，本需求阶段只固定业务口径。

### 14. 进度驾驶舱

进度驾驶舱是查看型页面，负责概览和进入明细，不直接编辑项目、阶段或任务。一期保留三块内容。

#### 14.1 核心指标卡

展示五个数量指标：

- 项目总数：当前用户有权限查看的顶级项目数量。
- 进行中项目数：当前用户有权限查看的顶级项目中，状态为进行中的项目数量。
- 逾期项目数：当前用户有权限查看的顶级项目中，命中已逾期预警的项目数量。
- 风险项目数：当前用户有权限查看的顶级项目中，人工风险为有风险或已偏离，或存在下级风险预警的项目数量。
- 阻塞项目数：当前用户有权限查看的顶级项目中，自身或下级存在未解除阻塞的项目数量。

核心指标卡不展示平均进度或整体完成率，避免将多个顶级项目强行压缩成一个误导性百分比。

#### 14.2 项目进度概览

口径：当前用户有权限查看的、状态为进行中的顶级项目。

展示形式：

- 上方展示进度区间柱状图，区间为 `0-25%`、`26-50%`、`51-75%`、`76-100%`。
- 下方展示简洁项目进度列表，仅展示项目名称、进度条和进度百分比。

异常表达：

- 进度条红色：项目命中已逾期预警，或人工风险为已偏离，或存在未解除阻塞。
- 进度条黄色：项目命中临近逾期、进度滞后、下级风险、里程碑风险任一预警，或人工风险为有风险。
- 默认色：未命中上述异常。
- 红色优先于黄色。
- 可在项目名称或进度条右侧展示风险、预警、阻塞三类异常图标。
- 不做悬停复杂提示；点击项目名称、进度条或异常图标均进入项目详情。

#### 14.3 风险与阻塞汇总

该区域采用异常明细视角，不强制按顶级项目聚合。

展示结构：

- 三个数字：风险对象数、预警对象数、未解除阻塞数。
- 三个图：人工风险分布、系统预警分布、阻塞类型分布。

口径：

- 风险对象数：当前用户有权限范围内，人工风险为有风险或已偏离的项目、阶段、任务数量。
- 预警对象数：当前用户有权限范围内，命中任一系统预警的项目、阶段、任务、里程碑数量。
- 未解除阻塞数：当前用户有权限范围内未解除的阻塞记录数量。
- 人工风险分布只展示有风险和已偏离，不展示正常。
- 系统预警分布按已逾期、临近逾期、进度滞后、下级风险、里程碑风险统计。
- 阻塞类型分布按外部依赖、内部协作、资源不足、决策待定、环境/系统问题、其他统计。

点击风险、预警或阻塞图表项时，跳转到风险与阻塞菜单下对应列表，并携带对应筛选条件。具体列表字段和筛选项在风险与阻塞菜单需求阶段继续确认。

### 15. 项目管理页面

项目管理页面采用左右分栏。左侧是可筛选树形项目卡片列表，右侧是选中项目详情工作区。

项目列表默认展示顶级项目，支持展开子项目，最多展示到第 3 层。筛选命中子项目时，左侧自动展开所属父级并选中命中项目；右侧展示该项目详情。驾驶舱跳转到项目管理时，通过路由携带筛选条件，左侧展示筛选标签，可单项移除或一键清空。

#### 15.1 左侧常驻筛选

| 筛选项 | 控件 | 数据来源 | 约束 |
|---|---|---|---|
| 关键词 | 输入框 | 用户输入 | 支持项目名称、项目编号、负责人搜索；最多 100 字符；带清空按钮 |
| 快捷筛选 | 可选标签/分段按钮 | 系统固定枚举和后端统计口径 | 单选：全部、进行中、风险、阻塞、逾期 |
| 高级筛选入口 | 筛选图标按钮 | 当前筛选状态 | 打开筛选抽屉或浮层 |
| 已选条件 | 筛选标签 | 当前筛选条件 | 支持单项移除和全部清空 |

#### 15.2 高级筛选

| 筛选项 | 控件 | 数据来源 | 约束 |
|---|---|---|---|
| 项目状态 | 多选下拉框 | 系统固定整数枚举 | 可选未开始、进行中、已暂停、已完成、已取消、已归档；具体状态矩阵后续确认 |
| 风险等级 | 多选下拉框 | 系统固定整数枚举 | 可选正常、有风险、已偏离 |
| 系统预警 | 多选下拉框 | 系统固定枚举 | 可选已逾期、临近逾期、进度滞后、下级风险、里程碑风险 |
| 阻塞状态 | 单选下拉框 | 系统固定枚举和阻塞记录 | 可选全部、有未解除阻塞、无未解除阻塞、自身阻塞、下级阻塞 |
| 计划完成时间 | 日期范围选择器 | 用户输入 | 只保留开始日期和结束日期，不做今天/本周/本月快捷项 |

#### 15.3 项目卡片

项目卡片展示项目名称、项目编号、负责人姓名、项目状态、当前进度、风险/预警/阻塞、计划完成时间和子项目数量。不展示项目层级标识，不提供复制项目编号操作。

左侧操作包括新建项目、刷新列表、选择项目、展开/收起子项目、编辑项目基本信息、清空筛选。所有创建按钮统一叫“新建项目”，是否创建顶级项目或子项目由点击入口决定。

完成、取消、归档、删除等高影响项目操作不放在左侧卡片区，后续在操作全集和状态矩阵中统一确认。

#### 15.4 项目基础表单

| 字段 | 控件 | 数据来源 | 约束 |
|---|---|---|---|
| 项目名称 | 输入框 | 用户填写 | 必填；最多 100 字符；同一上级项目下不允许重名 |
| 项目编号 | 只读文本 | 后端生成 | 创建后生成；全局唯一；不可编辑 |
| 上级项目 | 只读文本 | 点击入口带入 | 顶级项目显示 `无`；子项目显示上级项目路径；不可编辑 |
| 负责人 | 用户选择器 | 用户/组织接口 | 必填；单选；默认当前用户 |
| 项目成员 | 用户多选器 | 用户/组织接口 | 非必填；负责人自动纳入成员 |
| 计划开始时间 | 日期选择器 | 用户填写 | 非必填；不能晚于计划完成时间 |
| 计划完成时间 | 日期选择器 | 用户填写 | 非必填；不能早于计划开始时间 |
| 项目描述 | 多行文本框 | 用户填写 | 非必填；最多 1000 字符 |

新建和编辑时上级项目均不可选。风险等级不放在项目基础信息表单中，后续在风险与阻塞页签维护。项目状态相关操作先后置。

#### 15.5 右侧项目详情页签

顶部区域暂不确认，先确认各页签信息后再决定顶部区域最小内容。

当前页签为：基础信息、阶段与里程碑、任务、风险与阻塞、成员与记录。删除原“概览”页签，改为“基础信息”页签；基础信息不查统计数量。删除“子项目”页签，子项目通过左侧项目树表达和进入。

基础信息页签只展示项目名称、项目编号、上级项目、负责人、计划开始时间、计划完成时间、项目描述、创建人/创建时间、最后更新时间。基础信息页签不展示成员、不查询任务数、阶段数、里程碑数、阻塞数、预警数。

`编辑信息` 主入口放在基础信息页签内容区右上角，和“基础信息”标题同一行。只有项目负责人及以上角色展示；“以上角色”的精确定义后续在权限矩阵确认。左侧项目卡片更多菜单也保留编辑项目基本信息的快捷入口。

阶段与里程碑页签仅展示当前选中项目节点自身的阶段和里程碑，不包含下级项目。阶段一个列表，里程碑一个列表，不做详情页；不支持用户手工排序；不支持删除，仅支持作废。

阶段列表支持阶段名称输入框和阶段状态筛选，默认只展示启用阶段。字段包括阶段名称、阶段状态、阶段说明、关联任务数、关联里程碑数、派生进度、创建人、创建时间和操作。阶段列表按创建时间倒序；关联任务数可跳到任务页签并带入阶段筛选，关联里程碑数可在本页签里筛选该阶段。阶段派生进度仅来自该阶段下计入进度任务，无计入进度任务时显示 `-`，不参与项目上卷。

阶段新增和编辑表单只维护阶段名称、阶段说明。阶段状态只在列表展示，不出现在编辑表单中。已作废阶段不展示编辑和作废按钮。阶段作废需要填写作废原因并二次确认；作废前后端校验该阶段下是否存在未删除任务或未作废里程碑，存在时禁止作废，并提示用户查看关联任务或关联里程碑。

里程碑列表支持里程碑名称、类型、所属阶段和里程碑状态筛选。类型为项目级或关联阶段；所属阶段筛选只使用当前项目启用阶段；里程碑状态默认未作废。字段包括里程碑名称、类型、所属阶段、计划完成时间、实际完成时间、里程碑状态、说明、创建人、创建时间和操作。列表未完成优先，再按计划完成时间升序。未完成且计划完成时间早于当前日期时高亮计划完成时间；已完成且实际完成时间晚于计划完成时间时轻量标识延期完成；已作废不做逾期或延期高亮。

里程碑新增和编辑表单维护里程碑名称、里程碑类型、所属阶段、计划完成时间和说明。里程碑类型为项目级时清空阶段关联，类型为关联阶段时所属阶段必填。里程碑标记完成表单只填写实际完成时间和完成说明；更正完成信息表单只维护实际完成时间和完成说明；作废表单只填写作废原因。里程碑状态为未完成、已完成、已作废；未完成和已完成均可作废，已作废为终态。

新增/编辑项目使用宽模态框；阶段和里程碑相关新增、编辑、作废、标记完成、更正完成信息均使用普通模态框。项目状态为未开始、进行中、已暂停时允许阶段和里程碑维护；项目已完成时只允许更正已有里程碑完成信息；项目已取消或已归档时本页签只读。

阶段和里程碑操作均生成操作记录。新建类记录不提供对象明细点击；编辑类记录对象可点击查看字段名称、编辑前、编辑后的变更明细；作废、标记完成、更正完成信息可点击查看本次填写的信息，但不按字段前后值展示。动态记录列表归属成员与记录页签，本页签只负责触发操作和生成记录。

### 16. 进度快照

父任务和项目节点的当前进度可以保存系统计算后的快照，用于列表、排序、筛选和统计。该快照不是人工权威输入，任务或结构变化后由系统重新计算并覆盖。

阶段不作为项目进度计算单元；如展示阶段进度，该值仅作为列表展示派生值，不参与上卷。预警、风险和阻塞相关的数据存储与冗余汇总方式在概要设计阶段确定。

### 17. 枚举和空值

数据库枚举字段使用 `tinyint/int`，代码中做 Java/TypeScript 枚举映射。表结构尽量避免用 NULL 表示空值：ID 字段默认 `0`，文本默认空字符串，枚举默认 `0`，数值默认 `0`。时间字段如实际完成时间需进一步确认是否允许 NULL 或采用状态字段加哨兵值。

### 18. 权限与角色

已确认：

- 项目成员可见并协作。
- 部门负责人和管理员可看。
- 任务逻辑删除、取消/作废必须由项目管理员以上角色操作。
- 普通成员不能删除、取消/作废任务。
- 项目基础信息的 `编辑信息` 按钮仅项目负责人及以上角色展示。

待确认：

- 项目成员角色最终集合。
- 是否启用观察者角色。
- 普通成员可创建/编辑哪些任务。
- 部门负责人查看范围和数据权限实现细节。
- “项目负责人以上角色”的完整定义。

## Risks / Trade-offs

- [Risk] 阶段从进度汇总节点调整为任务分组维度后，需要清理旧的“阶段参与项目进度分母”口径。→ 本 change 文档已将阶段改为不上卷、不设权重，后续规格和表结构应沿用该口径。
- [Risk] 多层级项目树和递归进度统计复杂度较高。→ 一期限制项目树最多 3 层，父子项目汇总口径继续单独确认。
- [Risk] 新增任务导致进度下降可能引发用户误解。→ 在页面提示“项目范围扩大导致进度重算”，并记录操作记录。
- [Risk] 权重规则过复杂会影响解释性。→ 一期阶段不设置权重，任务权重采用相对权重、自动权重和有效权重展示，避免要求用户把同级权重凑成固定总和。
- [Risk] 状态与进度完全自动联动会误改用户管理判断。→ 任务状态由用户维护，项目状态相关高影响操作后续通过操作矩阵确认。
- [Risk] 驾驶舱统计口径混乱会造成数字不一致。→ 项目类指标明确使用顶级项目口径，风险与阻塞汇总明确使用异常明细视角。
- [Risk] 尽量不用 NULL 可能让实际完成时间等字段表达不自然。→ 对时间字段单独确认，避免使用不可靠的无效日期。

## Migration Plan

- 新增模块、表结构、菜单权限和前端页面，不迁移现有业务数据。
- 一期不改现有审校和工作流脚本。
- 回滚时删除新增菜单、权限、`brain_progress_*` 表和新增模块/前端目录。
